Create a high-end, production-ready responsive website redesign for a real Belarusian construction company:

ООО «ГАРАНТ КАЧЕСТВА»
Current website: https://garantk.by/

IMPORTANT:
This must look like a professionally art-directed website for an established construction contractor — NOT like a generic AI landing page, Bootstrap template, SaaS website, or simple wireframe.

For this first iteration DESIGN ONLY THE HOMEPAGE and establish a reusable visual design system.

The final design should feel credible enough that it could be presented to the actual company as a commercial redesign proposal.

==================================================
COMPANY / BUSINESS CONTEXT
==================================================

The company operates in construction and provides a range of construction, engineering, installation and finishing services.

The existing website contains real:
- construction services
- completed projects / objects
- projects in progress
- company information
- news
- contact information
- project photography

The strongest visual asset of the new website should be REAL CONSTRUCTION PROJECTS.

Do not invent:
- years in business
- number of completed projects
- number of employees
- certifications
- customer logos
- awards
- guarantees
- statistics
- testimonials
- business claims

unless explicitly supplied from source content.

If factual information is unavailable, omit it rather than inventing it.

==================================================
DESIGN DIRECTION
==================================================

Create a premium contemporary European construction-company aesthetic.

Visual characteristics:

- architectural
- confident
- established
- technically competent
- premium but restrained
- modern European B2B construction
- strong use of photography
- editorial typography
- generous whitespace
- strong grid
- subtle industrial character
- sophisticated asymmetry where appropriate
- clear hierarchy
- polished details

The visitor should immediately think:

“This is a serious company capable of delivering large construction projects.”

NOT:

“This is an AI-generated landing page.”

Use inspiration from the visual language of:
- premium European construction companies
- architecture studios
- engineering companies
- commercial real-estate developers

Do not copy any specific website.

==================================================
AVOID GENERIC AI DESIGN
==================================================

Absolutely avoid:

- four identical white cards in a row as the main layout
- excessive rounded cards
- floating glassmorphism panels
- purple / blue SaaS gradients
- random decorative gradients
- excessive shadows
- meaningless icons
- generic stock illustrations
- giant pill buttons
- fake KPI counters
- fake customer logos
- repetitive card grids everywhere
- huge empty dark areas without imagery
- text-only hero sections
- placeholder grey image boxes
- generic “Our advantages” icon grids
- making every section look like a component library demo

Cards should only be used where the content genuinely benefits from them.

Prefer editorial compositions, imagery, typography and layout.

==================================================
COLOR / MATERIAL FEEL
==================================================

Use a refined construction-oriented palette.

Primary:
deep charcoal / near-black / dark graphite.

Background:
warm off-white / architectural concrete white.

Accent:
restrained warm brass / construction yellow / muted gold.

Do NOT make gold dominant or luxurious in a hotel/jewelry sense.

It should feel like:
steel + concrete + architecture + precision.

Use accent color primarily for:
- CTA
- small labels
- lines
- active navigation
- subtle visual details

==================================================
TYPOGRAPHY
==================================================

Typography should be one of the strongest visual elements.

Use a modern high-quality sans-serif suitable for Cyrillic.

Create clear hierarchy:

small uppercase eyebrow
large editorial hero headline
strong section headings
comfortable body copy
compact technical metadata

Hero headline should feel architectural and bold, not like default H1 styling.

Do not use overly wide line lengths.

==================================================
GRID
==================================================

Desktop target width:
1440px

Content max-width:
approximately 1200–1280px.

Use a strong 12-column grid.

Create intentional differences in:
- section rhythm
- image size
- text width
- alignment

Do not simply center everything.

Use asymmetric compositions where they improve visual quality.

==================================================

Create a premium minimal header.

Left:
company logo / wordmark.

Navigation:

Mobile:
create a real mobile navigation pattern, not simply the word “Меню”.

==================================================
HERO — CRITICAL
==================================================

The current generated hero is too empty and has no visual impact.

Create a visually strong hero based around REAL construction photography.

Possible composition:

large full-width or large offset architectural/project photograph

with:
- eyebrow
- strong headline
- concise positioning text
- primary CTA
- secondary link

Headline direction:

“Строим объекты,
которые работают на бизнес”

or

“Комплексное строительство
и инженерные решения”

Use these only as copywriting direction.
Do not introduce unsupported facts.

The hero image should dominate the first screen.

Avoid a generic dark rectangle with text floating inside it.

Optionally use restrained technical/architectural details:
- grid lines
- project metadata
- vertical rule
- project category
- location label

but keep them subtle.

==================================================
PROJECTS — MOST IMPORTANT SECTION
==================================================

Projects should visually sell the company.

Do NOT show projects as grey placeholders.

Create a strong editorial portfolio section:

“Реализованные объекты”

Use large real project photography.

The first featured project may span approximately 60–70% of the width.

Other projects may use varied but consistent image layouts.

Each project may show:

project title
category
location if available
status if available

Possible statuses:
Завершён
В строительстве

Do not invent metadata that is unavailable.

Use image hover interactions on desktop.

Provide:
“Все объекты →”

This section should feel closer to an architecture portfolio than an e-commerce card grid.

==================================================

==================================================

Create a strong final conversion section before the footer.

Example visual direction:

real contact details

“Связаться с нами”

Do not repeat raw scraped navigation/content strings.

==================================================

==================================================

Create a professional multi-column footer containing actual:

Keep the visual language consistent with the header.

==================================================
REAL CONTENT / SCRAPED CONTENT
==================================================

IMPORTANT:

The source data may contain noisy scraped text such as:

“Skip to content”
“Previous”
“Next”
navigation labels
duplicated phone numbers
raw menu text

These are crawler artifacts.

DO NOT display crawler artifacts in the website.

Clean and semantically classify incoming content before placing it into the design.

A news headline must not become a service.
A certificate page must not become a project.
Contact text must not be repeated inside every card.

If content cannot be confidently classified, omit it from the homepage.

==================================================
IMAGE REQUIREMENTS
==================================================

Photography is critical.

Use actual company/project images from provided source assets whenever available.

Do not create empty grey placeholders.

If an image asset is temporarily unavailable in Figma, use a realistic architectural/construction image placeholder so that the DESIGN can still be evaluated visually, but clearly mark it as a replaceable image asset.

The production implementation will replace placeholders with actual imported CMS media.

Use:
- large images
- strong crops
- consistent treatment
- intentional aspect ratios

Avoid dozens of tiny thumbnails.

==================================================
RESPONSIVE DESIGN
==================================================

Design three intentional responsive layouts:

Desktop:
1440px

Tablet:
768px

Mobile:
390px

Mobile MUST be redesigned for the viewport.

Do not merely stack desktop elements vertically.

On mobile:
- keep hero visually strong
- preserve photography
- reduce heading sizes intelligently
- keep touch targets large
- simplify navigation
- avoid excessive vertical whitespace
- avoid extremely long cards
- make project imagery prominent
- maintain clear visual rhythm

==================================================
CMS / REUSABILITY REQUIREMENT
==================================================

This design will be implemented on top of a reusable CMS.

Therefore sections must map to reusable data components:

Header
Hero
Services
Projects
About
Process
News
CTA
Contacts
Footer

Do not hardcode company-specific layout logic.

The visual design may be unique, but content must remain dynamic.

Projects, services and news can contain a variable number of records.

==================================================
QUALITY BAR
==================================================

Before finishing, critically review the generated page.

Ask:

Would a professional web design studio confidently present this redesign to a construction company as paid work?

Does it look substantially better than the current garantk.by website?

Does the page rely strongly enough on actual construction/project photography?

Does it look custom-designed rather than generated from a generic template?

Is there a strong visual hierarchy?

Are Projects clearly more important than News?

Are Services real services rather than misclassified scraped content?

Does the mobile version feel intentionally designed?

If any answer is NO, improve the design before finishing.

Deliver:
1. polished desktop homepage
2. polished tablet homepage
3. polished mobile homepage
4. design system
5. reusable components

Do NOT generate the internal pages yet.
